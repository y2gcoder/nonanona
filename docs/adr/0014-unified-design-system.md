# 두 앱이 함께 쓰는 디자인 시스템

상태: accepted (2026-11-28, 사용자 합의). [모바일 디자인 기준](../design/mobile-foundations.md)의 "생김새는 각 플랫폼의 시스템 스타일을 따른다", "공유 UI 코드, 토큰 생성기, Figma, 디자인 시스템 라이브러리는 두지 않는다", "브랜드 색은 아직 정하지 않았다", "임시 중립 팔레트"를 대체한다. 그 문서의 역할 이름, 문구, 상태 라벨 규칙은 그대로다.

지금까지는 역할 이름과 문구만 맞추고 생김새는 각 플랫폼 기본에 맡겼다(무채색 임시 팔레트). 송금표·빈 화면처럼 서비스를 알아보게 하는 화면과 브랜드 색을 넣으려면, 두 앱이 같은 값과 같은 부품 모양을 써야 한다.

## 결정

- **두 앱은 하나의 디자인 시스템을 쓴다.** 같게 맞추는 것은 색 토큰(라이트·다크), 글자 단계, 간격, 둥글기, 부품의 모양(버튼, 목록 행, 금액 표시, 상태 라벨, 탑승권 모양의 송금표, 빈 화면), 문구다.
- **조작과 시스템 화면은 플랫폼 기본을 쓴다.** 내비게이션과 뒤로 가기 제스처, 시트, 날짜 선택기, 공유 시트, 사진 선택기, 시스템 알림, 햅틱, 시스템 글자 크기 설정, 로그인 버튼(제공자 공식 모양)이다. 사용자가 손에 익힌 동작과 플랫폼 지침을 지키기 위해서다.
- **기준 원본은 Claude Design System 아티팩트 "노나노나 디자인 시스템"이다**(<https://claude.ai/artifact/7r1KJ8kyhWzBKa6RCzDX3U>, 비공개). 저장소에는 토큰을 JSON으로 두고, 생성 스크립트로 두 앱의 테마 파일을 만든다. 생성 결과가 커밋된 테마 파일과 다르면 CI가 막는다. 생성기와 앱 반영은 따로 구현한다.
- **방향.** 평소 화면은 "맑은 하늘"이다. 덜어낸 화면에 하늘색은 주 동작과 강조에만 쓴다. 탑승권 모양은 송금표에만, 비행기 친구는 앱 아이콘·빈 화면·완료 화면에만 둔다. 글꼴은 두 앱 모두 Pretendard다. 다크 모드를 지원한다.

## 대가

- 원본이 저장소 밖(비공개 아티팩트)에 있다. 저장소 기여자는 토큰 JSON만 볼 수 있고, 원본과 JSON이 어긋나지 않게 옮기는 일은 사람이 한다.
- 생성기와 CI 검사를 새로 만들고 지켜야 한다.
- Pretendard를 두 앱에 넣어 앱 크기가 늘고, 시스템 글꼴의 글자 크기 단계를 직접 맞춰야 한다.
- 플랫폼 기본에서 벗어난 부품은 접근성(명암비, 큰 글자, 화면 읽기)을 앱이 직접 확인해야 한다.
