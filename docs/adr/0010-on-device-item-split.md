# 품목별 나누기: 품목은 기기에 두고, 사람마다 원 단위 몫만 방장 검토로 보낸다

상태: accepted (2026-11-24, 로컬 슬라이스, 이슈 #6 첫 조각). [ADR-0006](0006-room-settlement.md)의 남은 질문 "품목을 여행방에 올릴지, 기기에서만 몫 계산에 쓰고 결과 몫만 올릴지"에 대해 이번 슬라이스는 **결과 몫만** 쪽을 택한다. 단, 영수증을 올린 기기가 곧 방장 기기일 때만 품목 나누기를 연다. 다른 기기에서 올린 영수증의 품목을 방장이 보는 길은 따로 결정할 일로 남긴다(아래 "정하지 않은 것").

사용자가 베타 범위(일본어 영수증 품목 번역과 품목별 나누기)를 승인했다. 품목 글자(OCR 줄)·원래 이름·사진은 지금도 기기 밖으로 나가지 않는다([ADR-0003](0003-mobile-architecture.md), [ADR-0005](0005-receipt-review-and-mask-correction.md)). 이번 결정은 그 경계를 넓히지 않고 품목별 나누기를 만든다. 코드는 iOS `Packages/ReceiptImport`의 `ReceiptItems.swift`, `App/ItemSplitView.swift`, `Features/ReceiptImport/ItemTranslation.swift`, Android `feature/receiptimport/ReceiptItems.kt`·`ItemTranslation.kt`, `ItemSplitScreen.kt`다.

## 결정

- **품목 후보는 OCR 위치로 보수적으로 뽑는다**(`receipt-items-v1`). 세로 가운데가 맞는 OCR 상자를 한 행으로 묶는다(합계 찾기와 같은 기준). 행 끝에 가격 표시(¥, 円, 또는 따로 읽힌 숫자 상자)가 있어야 품목 후보다. 전화·카드 줄과 날짜 줄은 건너뛴다. 소계·세금·합계·결제·할인 줄은 요약으로 따로 두고 품목에 넣지 않는다. 첫 소계·합계 줄 아래의 가격 줄도 품목이 아니다. 부호가 붙은 금액은 할인 요약이다. 이름이 없거나, 금액을 읽지 못했거나, 수량 표시가 있거나, 합계보다 큰 줄에는 표시를 붙인다(`ItemFlag`). 표시가 있는 줄은 방장이 고치거나 "확인함"을 눌러야 나눌 수 있다. 줄 ID는 그 행의 가장 작은 OCR 줄 ID(`ocr-N`)다. 사용자가 더한 줄은 다시 쓰지 않는 번호(`manual-N`)다. 두 앱은 공통 예제(`apps/fixtures/items/examples.json`)로 같은 답을 내는지 본다.
- **계획은 기기 초안 폴더에만 둔다.** `items/<사진>.json`에 원자적으로 쓴다. 고칠 때마다 순번을 붙여 쓰고, 늦게 도착한 옛 입력은 덮지 않는다. 쓰기 실패는 "저장하지 못했어요 · 다시 저장"으로 보인다. 확인한 영수증(가린 사본이 있는 것)만 계획을 가진다. 영수증 합계와 통화는 확인한 값과 같아야 쓴다. 직접 입력(사본 없음)과 소수 자릿수 통화는 계획이 없다. 기기 밖으로 보내는 경계(`outboundReceipts`)는 바뀌지 않는다.
- **세금·할인·차이는 저절로 나누지 않는다.** 줄 합계가 확인한 영수증 합계와 다르면 차이를 보이고 계산하지 않는다(`totalMismatch`). 방장이 조정 줄(세금·수수료·할인, 할인은 음수)을 더하고 누가 낼지 정해야 한다. 비율 배분 같은 정책은 만들지 않았다.
- **몫은 정확한 분수로 계산한다.** 한 줄을 k명이 고르면 1/k씩이다. 공통 분모로 사람마다 정수 분자를 둔다. 엔화 영수증은 방장이 검토에서 정한 원화(실제 청구액·환전 원가·기준환율 예상, ADR-0008)를 분자 비율로 나눈다. KRW 영수증은 금액 그대로다. 사람마다 몫이 원 단위로 나눠떨어질 때만 정확한 몫이다. 두 사람 몫이 똑같고 원화가 홀수이며 결제자가 둘 중 한 명이면 [ADR-0007](0007-two-person-even-split.md)을 그대로 쓴다(결제자 +1원). 그 밖에는 내림한 몫과 남은 원을 보이고, 남은 원은 방장이 직접 정한다. 한 사람 몫이 0 이하(할인 때문)면 계산하지 않는다.
- **결과는 "직접 나누기" 입력으로만 들어간다.** "직접 나누기에 채우기"는 지출 검토의 직접 나누기 칸을 채우고 검토 화면으로 돌아갈 뿐 서버에 보내지 않는다. 방장이 확인하고 "포함하기"를 눌러야 기존 `review_expense`로 사람마다 원 단위 몫(`expense_shares`)만 간다. 서버 계약·요청 지문·확정 스냅숏은 그대로다. 서버는 지금처럼 합 = 원화만 검사한다. 나눠떨어지지 않아 내림한 몫만 채우면 검토 화면이 "1원이 남았어요"를 보이고 포함할 수 없다. 방장이 누가 낼지 적어야 포함된다.
- **이 기기에서 올린 영수증만 품목으로 나눈다.** 방장 검토는 장부의 사본 해시와 확인한 값(날짜·금액·통화)이 모두 같은, 이 기기의 확인한 영수증을 찾는다. 없으면 "다른 기기에서 올려 품목으로 나눌 수 없어요"를 보인다. 방장이 직접 올린 영수증이면 품목 글자가 방장 기기에만 있고, 방장이 이미 할 수 있는 동작(직접 나누기 몫 보내기)만 쓴다. 그래서 새 공유 필드·새 동의 없이 기존 권한과 경계 안에서 끝난다.
- **번역은 기기 안 제공자만, 언어 받기는 사용자가 고른다.** iOS는 Apple Translation이다. `LanguageAvailability`로 상태를 본다. 언어가 있으면 `TranslationSession(installedSource:target:preferredStrategy: .highFidelity)`(iOS 26.4+)로 번역한다. 지원하지만 언어가 없으면 "언어 받기"를 눌렀을 때만 `.translationTask` + `prepareTranslation()`의 시스템 창으로 사용자의 허락을 받는다. Android는 플랫폼 기기 번역(`android.view.translation.TranslationManager`, API 31+)이다. 새 의존성과 네트워크 권한을 더하지 않는다. 서비스가 없거나 언어 쌍이 없으면 Unsupported다. 언어를 받아야 하면 기기 번역 설정 화면을 연다(있을 때). 번역 결과는 이름이 비었거나 기계가 채운 줄에만 들어간다. 사용자가 적은 이름은 덮지 않는다. 실패하면 아무것도 바꾸지 않고 "다시 번역하기"와 직접 입력을 둔다. 원문 행은 언제나 같이 보인다.
- **미리보기 대역은 실제 번역과 섞이지 않는다.** debug 빌드에만 정해 둔 사전(`PreviewItemTranslator`, 가상 영수증 품목 8개)이 있다. iOS 실행 환경 `NONANONA_ITEM_TRANSLATION=preview`, Android `debug-processing.properties`의 `itemTranslation=preview`일 때만 쓴다. 이름 출처(`NameSource.preview`)와 화면 문구 "미리보기 대역 · 실제 번역 아님"으로 언제나 따로 표시한다. release에는 없다.

## 대가

- 회원이 올린 영수증(대부분의 경우일 수 있다)은 방장이 품목으로 나눌 수 없다. 방장이 지금처럼 직접 나눈다.
- 엔화 영수증은 원화가 사람마다 나눠떨어지는 일이 드물다. 그때마다 방장이 남은 몇 원을 직접 적는다. 대신 반올림·잔여 원 정책을 새로 만들지 않았다.
- 세금이 따로 붙는 영수증(외세)은 방장이 세금 줄을 직접 더하고 나눠야 한다.
- 검토 입력(결제자·원화)은 지금처럼 메모리에만 있다. 앱을 다시 열면 다시 적는다. 품목 계획은 남는다.
- 실제 번역 경로를 휴대폰에서 끝까지 확인하지 못했다. iOS 시뮬레이터는 Apple Translation이 번역하지 않는다(Apple 문서, 실제로 ja→ko를 쓸 수 없다고 알림). 같은 API는 macOS 호스트에서 `.highFidelity`로 번역했다(`.lowLatency`는 설치 상태와 달리 `notInstalled`). Android 에뮬레이터의 플랫폼 기기 번역 서비스(Android System Intelligence)는 16개 언어만 알리고 한국어가 없어 ja→ko를 쓸 수 없다. 플랫폼 길로는 한국어가 없는 기기가 많을 수 있다(실기기 확인 필요).
- 실제 OCR은 품목 글자를 틀리게 읽는다(ML Kit: 唐揚げ→唐場げ, `¥1,320`→`41.320`). 추출은 마침표도 자릿수 구분으로 받아 41,320엔을 만들었지만, 합계 초과 표시와 줄 합계 불일치로 계산 전에 막혔다. 번역은 OCR 글자를 그대로 넣으므로 원문 행을 언제나 같이 보인다.

## 정하지 않은 것 (제품 결정)

- **다른 기기에서 올린 영수증의 품목을 방장이 볼 수 있게 할지.** 선택지는 셋이다. (a) 올린 사람이 자기 기기에서 품목 몫을 정해 "제안 몫"(사람마다 원, 품목 글자 없음)으로 올린다. 이때는 새 RPC·필드, 올린 사람의 몫 제안 권한, 방장 승인 흐름이 필요하다. (b) 품목 줄(이름·금액)을 여행방에 올린다. 이때는 새 동의 화면, 번역 이름 전송, 저장·삭제 기한을 정해야 한다. (c) 지금처럼 올린 기기에서만 나눈다. 이번 슬라이스는 (c)다.
- 외세 영수증의 세금을 품목 비율로 나눌지(잔여 원 규칙 포함), 할인을 어디에 붙일지.
- 세 명 이상 균등 나누기의 잔여 원 규칙(ADR-0007 미정과 같은 질문).
- Android ML Kit 번역(`com.google.mlkit:translate` 17.0.3, 2024-08-07 게시)을 쓸지. 이 라이브러리는 언어 모델(약 30MB)을 Google에서 받는다. 그러려면 release에 네트워크 권한(INTERNET)이 필요하다. 지금 release 앱에는 네트워크 권한이 없다. 권한을 더하고 모델 받기 동의를 받을지는 따로 결정한다. 이번에는 쓰지 않았다.
