# 품목 재번역 결과는 끝낼 때까지 기기 초안 폴더에 남기고, 끊긴 요청은 다시 보내지 않는다

상태: 채택 (2026-11-26). [ADR-0010](0010-on-device-item-split.md)의 기기 안 초안 폴더 경계를 넓히지 않는다. 품목 계획(`items/<사진>.json`) 옆에 같은 방식의 파일을 하나 더 둘 뿐이다. 코드는 Android `ItemRetranslationState.kt`·`ItemRetranslationDialog.kt`·`feature/receiptimport/StoredItemRetranslation.kt`, iOS `App/ItemRetranslation.swift`·`App/ItemRetranslationSheet.swift`와 `Packages/ReceiptImport`의 `ItemRetranslationRecord`다. 두 앱의 동작은 [apps/README.md](../../apps/README.md)의 ‘품목명 다시 번역’ 항목에 있다.

2026-11-26 Galaxy A24 실기기 시험에서 화면을 깨우려고 누르다 재번역 결과 대화상자 바깥을 눌렀다. 대화상자가 닫히면서 이미 비용을 쓴 번역 결과도 함께 사라졌다. 요청과 결과가 화면(Compose 컴포지션, SwiftUI `@State`·`.task`)에만 있었기 때문이다.

## 결정

- **받은 결과와 보낸 요청 표시를 기기에만 둔다.** 받았지만 사용자가 적용하거나 ‘닫기’로 끝내지 않은 결과, 그리고 보낸 뒤 응답을 기다리던 요청 표시를 영수증 초안 폴더의 `retranslations/<사진>.json`에 둔다. 품목 계획과 같은 원자적 쓰기와 같은 보호를 쓰고, 백업에서 빠지며, 기기 밖으로 보내거나 동기화하지 않는다. 요청과 결과는 화면보다 오래 사는 소유자(Android `AppViewModel`, iOS `AppModel`)가 가진다.
- **결과는 영수증·품목 ID·원문 스냅샷에 묶는다.** 다시 실행해 그 영수증의 품목 화면에 들어오면 결과를 다시 보인다. 그사이 품목 원문이 바뀐 줄은 버린다. 적용한 줄과 ‘닫기’로 끝낸 결과는 지운다. ‘이 이름 사용’은 지금처럼 누른 줄에만, 스냅샷이 같을 때만 적용된다.
- **끊긴 요청은 저절로 다시 보내지 않는다.** 응답을 기다리다 앱이 끝났으면 다음 실행에서 “번역 제안을 받지 못했어요”와 ‘다시 시도’를 보인다. ‘다시 시도’는 동의 단계로 돌아갈 뿐이고, 사용자가 “확인하고 다시 번역”을 눌러야 보낸다.
- **요청 중과 결과 단계는 실수로 닫히지 않는다.** 바깥 터치, 뒤로 가기, 아래로 쓸기로 닫히지 않고 결과 단계에서 ‘닫기’로만 닫힌다. 요청 중에는 ‘닫기’도 꺼져 있다. 대신 응답 대기에 40초 상한을 둔다. 상한을 넘기거나 어댑터가 취소로 끝나면 같은 실패 안내로 간다. 동의와 줄 선택 단계는 지금처럼 쉽게 닫힌다.

## 대가

- 서버에서 끝난 응답이라도 기기가 받지 못하면 다시 받을 길이 없다. 사용자가 다시 보내면 비용이 한 번 더 든다. 대신 사용자 모르게 같은 비용을 두 번 쓰지는 않는다.
- 요청 중에는 최대 40초 동안 대화상자를 닫을 수 없다.
- 기기 저장 실패, 일시적인 읽기 실패, 지우기 실패마다 따로 안내와 다시 하기를 둔다. 상태가 늘어난 만큼 두 앱의 테스트도 늘었다.

## 범위 밖

- 서버 요청 ID로 결과를 다시 받아 오는 경로(Worker 변경)
- 묶음 크기에 맞춘 HTTP 읽기 제한 조정
- 운영 번역 경로 연결. 지금 두 앱은 debug 미리보기 사전으로만 재번역한다.
