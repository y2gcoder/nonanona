# Android 한국어 OCR과 두 앱의 언어 선택 규칙

상태: accepted (2026-11-26, 사용자 합의). [ADR-0005](0005-receipt-review-and-mask-correction.md)의 "현재 Android 구현"에서 한국어 OCR 모델을 포함하지 않는다는 줄과 "현재 iOS 구현"의 한국어 인식 확인 조건(가나가 적은 사진만)을 대체한다.

제품 범위의 결제 화면 캡처(숙소 예약 화면, 항공권 결제 메일, 토스 인출·환전 내역)는 한국어다. iOS는 Vision에 `ko-KR`을 넣어 읽었지만 Android는 ML Kit 일본어 모델만 있어 한국어 화면에서 합계와 한국어 라벨(승인번호 등)을 읽지 못했다.

## 결정

- **Android에 ML Kit 번들 한국어 모델을 넣는다.** `com.google.mlkit:text-recognition-korean` 16.0.1(일본어 모델과 같은 판·같은 공통 엔진). 여행 중 네트워크가 약할 수 있어 Play 서비스 동적 다운로드는 쓰지 않는다. release APK는 54,582,043 → 55,106,643 B(+524,600 B, +0.96%)다. 늘어난 것은 ABI와 무관한 모델 자산이고 ABI별 네이티브 라이브러리는 그대로다.
- **사진마다 두 언어로 모두 읽고 두 앱 같은 규칙으로 고른다.** Android는 일본어·한국어 모델, iOS는 일본어·영어 우선 읽기와 한국어를 포함한 자동 감지 읽기다. 점수는 줄마다 (공백을 뺀 글자 수 × 엔진 줄 신뢰도)의 합이다. 한국어 결과의 한글 줄이 2줄 이상이고 점수가 일본어 결과보다 높을 때만 한국어 결과를 쓰고, 같으면 일본어(예전 동작)다. 한국어 읽기가 실패하면 일본어 결과를 쓴다. 규칙은 공통 표 `apps/fixtures/korean/language-choice.json`으로 두 앱이 함께 시험한다. 신뢰도의 척도는 엔진마다 다르므로 같은 것은 식과 조건이고 문턱값을 엔진끼리 비교하지 않는다.
- **조건부로 한 번 더 읽지 않는다.** 일본어 결과만 보고 한국어 읽기를 건너뛰는 조건을 찾지 못했다. 가상 입력 448장(일본어 336, 한국어 112)에서 ML Kit 일본어 모델은 한국어 화면의 한글을 가나·한자로 잘못 읽어 기준 4장에서 가나 줄을 2~4줄 만들었고, 한국어 모델은 일본어 영수증에서 한글 줄을 최대 8줄 만들었다. iOS의 예전 조건(일본어 읽기의 가나 줄 2줄 미만)은 한국어 112장 중 78장만 한국어로 골랐고, 일본어 가게·상품 줄이 2줄 섞인 한국어 결제 화면(k04)을 놓쳤다. 한국어 입력을 놓치면 한국어 라벨을 읽지 못해 가림이 약해지므로 처리 시간을 더 쓴다.
- **합계·통화·날짜를 한국어 입력에 맞춘다(두 앱 같은 규칙, 공통 표 `proposal-fields.json`).** 합계 낱말에 `합계`·`결제 금액`·`총 금액`을 더하고 `小計`·`소계` 줄은 뺀다. 통화는 합계를 읽은 글자의 표시(`円`·`¥`·`JPY` / `원`·`₩`·`KRW`, ML Kit이 `₩`를 읽는 `W`+숫자)로 정하고, 없거나 둘 다면 표시가 붙은 줄이 많은 쪽, 그래도 같으면 한글 줄이 2줄 이상일 때 KRW, 아니면 JPY다. 날짜는 `년`·`월` 구분도 받는다.
- **한국어 가림 라벨을 두 앱에서 맞춘다.** `카드번호`·`승인번호`·`회원번호`·`예약번호`처럼 "번호"와 묶은 라벨과 `전화`·`연락처`다. Android는 `카드`·`예약` 같은 낱말만으로 라벨을 잡아 "예약 확정", "가상카드 일시불" 같은 화면 글자를 가렸다. iOS는 같은 행의 먼 칸에 있는 강한 번호가 이미 가려지면 그 라벨을 짝 있는 라벨로 본다(결제 화면의 "라벨 ……… 값" 행에서 "가림 확인 필요"를 띄우지 않는다). 공통 가림 시험에 한국어 8항목을 더했다.

## 대가

- 모든 사진을 두 번 읽는다. 이미지당 인식 시간(중앙값, 일본어 기준 11장)은 Android 에뮬레이터에서 32.4 → 47.1 ms, iOS 시뮬레이터에서 568 → 1,147 ms다(한국어 4장은 Android 34.8 → 74.0 ms, iOS는 예전 조건도 세 장을 두 번 읽어 960 → 959 ms). 사진 10장을 동시 2장으로 처리하면 iOS에서 약 3초가 늘어난다.
- APK가 0.5 MB 늘었다.
- 엔진 오독이 남는다. iOS 한국어 포함 읽기는 k04의 `¥2,480`을 `·2,480`으로 읽어 통화가 KRW로 제안되고(검토 화면에서 고친다), k03 영수증의 `합계` 라벨과 `6,900원`의 끝 글자를 놓쳐 합계를 찾지 못한다(직접 입력). iOS는 흐린 한국어 변형 3장에서 카드 번호 오독으로 번호를 가리지 못했고, 세 장 모두 "가림 확인 필요" 안내가 붙었다. Android는 긴 화면의 타일 겹침에서 같은 날짜를 `2026.10,20`으로 한 번 더 읽어 그 줄을 번호로 가리거나, `₩265,100`을 `W265100`으로 읽어 합계 줄을 가리는 경우가 변형 사진에서 있었다(보호 줄 과잉 가림 9/360).

## 확인할 것

- 실제 기기에서의 처리 시간과 배터리, 실제 결제 화면·메일 캡처에서의 선택 결과. iOS의 두 번 읽기 비용이 크면 한국어 포함 읽기 하나로 줄이는 방안(일본어 336장 중 285장은 두 읽기 결과가 같았다)을 따로 검증한다.
