# 영수증 검토와 가림 고치기

상태: accepted (2026-11-23)

영수증 10장을 받은 뒤 사용자는 목록에서 상태를 먼저 보고, 한 장씩 원본과 비교해 값과 가림을 확인한다(QA 권고: A의 목록을 첫 화면으로, B의 "확인하고 다음"을 연속 검토 경로로). 확인한 것만 기기 밖으로 나갈 수 있으므로([ADR-0003](0003-mobile-architecture.md)), 검토 화면의 결정은 무엇이 여행방에 올라가는지를 정한다.

## 결정

- **가림 고치기는 줄 켜기와 가로 띠다.** OCR이 찾은 줄은 줄마다 스위치(글자 크기를 따라 커지는 목록 행)로 가리거나 푼다. OCR이 줄을 찾지 못한 곳은 "가림 영역 더하기"로 가로 전체 띠를 더하고, 버튼(위로·아래로·넓게·좁게·삭제)과 화면 읽기 조절 동작으로 옮긴다. 위치는 사진 높이의 정수 퍼센트(이동 2%, 크기 1%)라 두 플랫폼이 같은 픽셀을 굽는다. 손가락으로 사각형을 그리는 방식은 화면 읽기·큰 글자·운동 제약 사용자가 쓸 수 없어 고르지 않았다. 대가: 띠는 같은 높이의 다른 정보도 덮고, 2% 단위보다 세밀하게 맞출 수 없다.
- **미리보기는 확인과 같은 굽기 함수다.** "가린 사본"은 확인 때 만들 PNG를 그대로 보여 주고 디스크에 쓰지 않는다. 화면 읽기에는 "가린 사본 미리보기, 가림 N곳"만 읽히고 가린 글자는 읽히지 않는다. 원본 보기의 OCR 줄 글자는 기기 안 검토에만 보인다.
- **읽지 못한 사진의 직접 입력은 값만 기기에 남긴다.** 사본 없이 확인(`confirmManual`)하고, 이번 단계에서는 올리지 않는다. 지금 서버(`submit_receipt_expense`)는 사본이 있는 지출만 받고, 흐린 원본을 사본으로 대신 보내지 않기 위해서다. 올리기 화면은 "직접 입력 N건은 이번에는 올리지 않아요"를 보인다. 사진 없는 지출을 서버에 넣는 일은 정산 단계에서 결정한다.
- **확인은 "확인하고 다음" 한 가지다.** 누르면 그 사진을 확인해 디스크에 쓰고(가린 사본 또는 직접 입력), 목록 순서(사진 번호)로 다음 "확인 필요" 사진을 연다. 뒤에 없으면 앞쪽, 그것도 없으면 목록으로 돌아가 남은 것(읽지 못함·읽는 중)을 보인다. 건너뛰기·나중에 버튼은 없다. 검토 화면을 나가도 확인되지 않는다. 확인한 사진은 고칠 수 없다(같은 사본으로 이미 올렸을 수 있어, 다시 만들면 다른 요청 키의 지출이 생긴다).
- **고치던 입력은 사진마다 디스크에 둔다.** 초안 폴더 `reviews/<사진>.json`(값 글자 그대로, 가릴 줄, 띠)에 고칠 때마다 원자적으로 쓰고 확인하면 지운다. 값이 비어 있으면 OCR 제안을 쓴다. 그래서 앱 종료, 창 배치 변경, 그 사진만 다시 읽기를 지나도 입력이 남는다.
- **검토 화면은 목록·상세의 상세 쪽에 붙인다**([ADR-0004](0004-adaptive-layout.md)). iOS는 분할 보기 상세 열 안의 쌓기(초안 위에 검토), Android는 세 번째 칸(`extraPane`, 두 칸이면 영수증 목록 옆)이다. 검토 화면 자체는 한 열로만 쌓아 접힘 피하기를 시스템 컨테이너에 맡긴다. 고른 영수증은 안정 ID(초안 ID + 사진 ID)로 모델에 둔다.
- **release에서도 검토·확인을 할 수 있다.** 올리기와 개발용 바로 확인 버튼만 debug 전용이다.

## 확인할 것

- 실제 기기의 VoiceOver·TalkBack 읽기 순서와 조절 동작, 실제 사용자 사진(긴 영수증, 기울어진 사진)에서 2% 띠가 충분한지.
- 사진 없는 직접 입력을 서버에 올릴 때의 요청 키와 중복 방지.
